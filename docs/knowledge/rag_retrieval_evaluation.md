# BlueCurrent RAG 检索评估记录

## 实验目的

验证知识库能否召回包含正确证据的文本块，并观察知识库范围外问题是否产生误召回。

## 第一轮固定参数

- Embedding：`text-embedding-v4`
- 相似度阈值：`0.2`
- 向量相似度权重：`0.5`
- 全文相似度权重：`0.5`
- Top N：`10`
- Rerank：关闭
- 知识图谱：关闭

> 第一轮保持较低阈值，用来收集分数。不要根据单个问题反复改参数。

## 评估标准

- **Top 1 命中**：排名第一的文本块包含回答问题所需的明确证据。
- **Top 3 命中**：前三个文本块合计包含回答问题所需的全部明确证据；复合问题允许证据分布在不同文本块中。
- **范围外拒绝**：知识库无法回答的问题没有返回结果，或后续系统明确拒绝作答。
- 只检查“是否检索到证据”，不要让通用大模型补充答案。

## 第一轮结果

- 可回答问题 Top 1 命中率：`5 / 8 = 62.5%`
- 可回答问题 Top 3 命中率：`8 / 8 = 100%`
- 范围外问题误召回数：`2 / 2 = 100%`
- 可回答问题的最低第一名分数：`0.4737`
- 范围外问题的最高第一名分数：`0.4521`
- 两者暂时间隔：`0.0216`

> 第一名分数不一定是正确证据块的分数。Q2、Q3、Q4 的正确证据并非都排在第一名，因此不能仅凭上述间隔直接确定最终阈值。

## 第二轮：阈值 0.46 临界测试

- 其他参数保持第一轮设置不变，向量权重仍为 `0.5`。

| ID | 返回数量 | 结果 |
|---|---:|---|
| Q2 | 1 | 命中 |
| Q3 | 2 | Top 3 命中 |
| Q4 | 1 | 只召回风险等级证据，缺少“4小时内发布首次说明” |
| Q6 | 1 | 命中 |
| Q9 | 0 | 正确拒绝 |
| Q10 | 0 | 正确拒绝 |

结论：阈值 `0.46` 可以过滤当前两个范围外问题，但同时过滤了 Q4 所需的第二个相关文本块，暂不能作为最终阈值。这说明复合问题的证据分散在不同文本块中，单纯提高阈值无法同时保证召回和拒答。

### Q4 证据定位

- 包含“4 小时内发布第一份公开说明”的文本块排名：第 2 名
- 该文本块混合相似度：`0.4314`
- 范围外问题最高分：`0.4521`

因为相关证据分数低于范围外结果，不存在一个仅靠相似度阈值就能同时保留该证据并过滤当前范围外问题的取值。下一步应优化知识组织，使同一个业务判断所需的条件、等级和响应时限位于自包含的知识块中。

## 第三轮：自包含知识卡优化

新增 `bluecurrent_p0_response_card.md`，将 P0 触发条件、风险等级和首次公开说明时限组织在同一个知识单元中。测试参数保持：

- 相似度阈值：`0.46`
- 向量相似度权重：`0.5`
- Top N：`10`
- Rerank：关闭

| ID | 优化后结果 |
|---|---|
| Q4 | 知识卡进入 Top 1，混合相似度 `0.4899`，同时包含“P0”和“4小时” |
| Q9 | 返回 0 条，正确拒绝 |
| Q10 | 返回 0 条，正确拒绝 |

### 优化效果

- Q4 完整证据排名：`第 2 名 → 第 1 名`
- Q4 完整证据分数：`0.4314 → 0.4899`，提高 `0.0585`
- 在阈值 `0.46` 下：`无法保留完整证据 → 可以保留完整证据`
- 当前范围外测试拒绝率：`2 / 2 = 100%`

结论：通过自包含知识卡优化知识组织，比继续微调单一阈值更有效。当前测试集下，`0.46` 阈值与 `0.5` 向量权重可作为 BrandPulse 集成 RAGFlow 的候选基线配置。



## 后续调参原则

1. 先保证 Q1–Q8 的相关证据能够进入 Top 3。
2. 再根据“最低相关分数”和“最高无关分数”选择相似度阈值。
3. 如果两类分数严重重叠，优先优化文档分块，不通过盲目提高阈值解决。
4. 参数确定后，需要同步到真正调用检索接口的配置中；检索测试页的临时改动不会自动保存。
